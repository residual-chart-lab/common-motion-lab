# Sol M0 — CMD 再記述版

日付：2026-09-28

基準原稿：Sol 第一稿固定版 `46b36ac363c047ad8393ceac7827521ee9c49766`

状態：**派生記述**。固定済み `model.md` は変更しない。

この文書は Sol 第一稿を Common Motion Diagram（CMD）へ**コンパイル**したもの。新しい模型を提案する文書ではない。元原稿の状態・操作・読み取り・拘束を保ったまま、主語を「状態」から「同じ差の追跡」へ移す。

---

## 0. CMD で何を保存するか

CMD v0.2 の原則に従い、次を保存する。

1. 同じ差の**由来**。
2. 操作の順序。
3. 読み取りが同じか異なるか。
4. 表示の帰還と全状態の帰還の区別。
5. 結果拘束の下で許容／排除される経路。
6. `stay` と `advance` を別操作として保持する。
7. 〈記憶〉〈原因〉などの語は、差そのものの別名ではなく、見る側の注記としてだけ置く。

### 担持タグ

この派生記述では、同じ追跡線 $D$ が「いまどこに現れているか」を示すため、補助的に

- $D[Z]$：完全状態側に担持
- $D[O]$：読み取りに差として現れている
- $D[C]$：結果拘束への応答差として現れている

と書く。

タグが変わっても、**別の差へ交換したとは扱わない**。由来が同じ追跡線なら $D$ は継続する。

## 1. 逆コンパイル用の最小マニフェスト

CMDだけを見て元の M0 を取り違えないよう、数理定義は裏側に固定する。

状態：

$$
Z=\mathbb Z/3\mathbb Z=\{0,1,2\}.
$$

読み取り：

$$
\Pi(0)=A,\qquad
\Pi(1)=A,\qquad
\Pi(2)=B.
$$

操作：

$$
\mathcal A=\{\text{stay},\text{advance}\},
$$

$$
U_{\mathrm{stay}}(z)=z,
\qquad
U_{\mathrm{advance}}(z)=z+1\pmod3.
$$

D検査で使う結果拘束：

- 初期状態：0
- 長さ：3
- 終端表示：A

$$
C(w)=1
\iff
|w|=3
\ \text{and}\ 
\Pi(U_w0)=A.
$$

この節は CMD の図に新しい意味を足さない。図から元の第一稿へ戻るための辞書。

# 2. CMD-S1 — 見えない差が、同じ操作で見える

追跡する差を

$$
D_0=(0,1)
$$

とする。

初期状態では

$$
0\neq1,
\qquad
\Pi(0)=\Pi(1)=A.
$$

したがって差は完全状態にはあるが、表示では見えない。

```text
          ○  A / A
     D[Z] : 0 | 1
              |
              | ● advance
              v
          ◎  A / B
     D[O] : 1 | 2
```

同じ `advance` を左右へ適用している。

$$
(0,1)
\xrightarrow{\mathrm{advance}}
(1,2).
$$

相対差は

$$
\delta=1
$$

のまま。

### この図から読んでよいこと

- 差は最初から存在する。
- 現在表示が同じでも全状態は同じではない。
- 同じ後続操作で差が読み取りへ現れる。
- 「隠れ状態」「後続識別」は、この一本の $D$ を別方向から読む語彙候補。

### 読んではいけないこと

- ○ の区間で差が消えた。
- ◎ の地点で新しい差が生成された。

# 3. CMD-S2 — 表示は帰るが、差は残る

単一軌道

$$
0\xrightarrow{\mathrm{advance}}1
$$

では、

$$
\Pi(0)=\Pi(1)=A.
$$

表示は同じだが、完全状態は更新されている。

CMD では、時点0と時点1を「同じ表示」として括る。

```text
      0歩                    1歩
   state 0                state 1
      ○ A                    ○ A
       |                      |
       +------ 同表示 --------+

       ● advance

   0 と 1 の差 = D[Z]
```

ここで表示の帰還を全状態の帰還へ置き換えない。

さらに「帰還前」と「帰還後」を二状態として同じ `advance` へ送る。

```text
          ○ A / A
     D[Z] : 0 | 1
              |
              | ● advance
              v
          ◎ A / B
     D[O] : 1 | 2
```

したがって、帰還後に残った差は次の同じ運動へ作用する。

### 語彙の注記

- 表示が同じまま差が残っている側から読む：〈保持〉〈記憶候補〉
- その差が次の表示を変える側から読む：〈原因候補〉

どちらも別線を作らない。同じ $D$ の読み方。

---

# 4. CMD-S3 — stay は差を「最近履歴の外」へ持ち越せる

Sol 第一稿の第二操作 `stay` の比較価値を、CMDで明示する。

初期差：

$$
D=(0,1),
\qquad
\Pi(0)=\Pi(1)=A.
$$

両方へ同じ `stay` を何回適用しても、

$$
(0,1)\xrightarrow{stay}(0,1)
\xrightarrow{stay}\cdots
$$

なので差は残る。

```text
          ○ A/A      ○ A/A      ○ A/A      ○ A/A
D[Z]  0|1 --stay--> 0|1 --stay--> 0|1 --stay--> 0|1
                                                   |
                                                   | ● advance
                                                   v
                                                ◎ A/B
                                                1 | 2
```

### CMD上の意味

- 最近の表示列は、任意に長く A/A のままにできる。
- 最近の操作列も、任意に長く stay/stay/... で一致させられる。
- それでも同じ差 $D$ は切れない。
- 後で同じ advance を入れると差が再び表示へ現れる。

したがって、Sol 型では

> 最近の固定長履歴から毎回再構成する記憶

と

> 以前の区別を現在状態として持ち越す記憶

を同一視しない。

### 重要な禁止

`stay` を「進んで戻った」と描き換えない。

```text
stay  !=  advance ; reverse
```

途中の表示・歩数・後続応答が違う。

# 5. CMD-S4 — 結果拘束の下で経路は一つに決まらない

結果拘束 $C$：

```text
start = 0
steps = 3
terminal readout = A
```

二つの許容経路を同じ枠の中に置く。

## 経路 α

$$
\alpha=(stay,advance,stay)
$$

```text
0 --stay--> 0 --advance--> 1 --stay--> 1
A           A              A          A
```

終端：

$$
state=1,\qquad readout=A.
$$

## 経路 β

$$
\beta=(advance,advance,advance)
$$

```text
0 --advance--> 1 --advance--> 2 --advance--> 0
A              A              B              A
```

終端：

$$
state=0,\qquad readout=A.
$$

CMDとしてまとめる。

```text
+-------------------- C : 3歩後に A --------------------+
|                                                         |
| α : 0 --stay--> 0 --advance--> 1 --stay-------> 1     |
|     A          A              A                A         |
|                                                         |
| β : 0 --advance--> 1 --advance--> 2 --advance--> 0     |
|     A              A              B              A       |
|                                                         |
+---------------------------------------------------------+

                    終端表示
                     ○ A/A
                       |
                  D_path[Z]
                     1 | 0
```

同じ結果表示に到達しているが、完全状態は違う。

この $D_{path}$ は、同じ初期状態から**異なる実現経路が分岐したこと**に由来する差。

A–Cで追った $D=(0,1)$ と、由来を曖昧にして一本へ混ぜない。

ただし終端の状態対は $1|0$ なので、その後へ同じ `advance` を適用すると

$$
1\to2\quad(B),
$$

$$
0\to1\quad(A).
$$

```text
             ○ A/A
D_path[Z]     1 | 0
                |
                | ● advance
                v
             ◎ B/A
D_path[O]     2 | 1
```

同じ結果の下に残った経路差が、次の同じ操作で再び読める。

# 6. CMD-S5 — 排除される経路を消さない

拘束 $C$ が本当に働いていることを示すため、排除経路も残す。

$$
\gamma=(stay,advance,advance).
$$

```text
0 --stay--> 0 --advance--> 1 --advance--> 2
A           A              A              B
```

終端表示が B なので

$$
C(\gamma)=0.
$$

CMDでは「候補経路」から消去してなかったことにしない。

```text
candidate γ
     |
     +-- C --> rejected
```

結果拘束は、枠の外から未来→現在への物理的作用方向を自動的には意味しない。

# 7. 第一稿 A–D との対応

| 第一稿検査 | CMDでの場所 | 保存された内容 |
|---|---|---|
| A 同じ表示・異なる全状態 | CMD-S1 初期 | $0|1$, ○ A/A |
| B 同じ後続操作で顕在化 | CMD-S1 | 同じ advance 後に ◎ A/B |
| C 非同一帰還 | CMD-S2 | 表示 A→A、全状態 0→1 |
| C 帰還後の差が次へ効く | CMD-S2 後半 | 同じ advance で A/B |
| D 同じ結果拘束・異経路 | CMD-S4 | α, β とも終端 A、状態は1/0 |
| D 拘束が実際に排除 | CMD-S5 | γ は終端 B で rejected |

A–Dの判定はCMDによって変更していない。

# 8. CMD変形規則による自己監査

## 8.1 配置変更

図の曲げ伸ばし、節点の位置変更は可。

次は変更しない。

- advance / stay の順序
- ○ / ◎ の位置
- 結果拘束の歩数
- 経路の許容／排除

## 8.2 名前変更

状態名や表示名を変更する場合は、全遷移と読み取りを保存する対応を併記する。

第一稿比較で得た Astra 核との

$$
f(z)=-z\pmod3
$$

の対応は、この規則で別途扱う。

この文書では Astra 案を Sol CMD の内部へ混ぜない。

## 8.3 操作のまとめ

複数の stay を

```text
stay^n
```

と省略してよい。

ただし

- 何回 stay したか
- 途中の表示が全て A/A だったこと
- 最後の advance で差が出ること

を必要に応じて復元できる場合に限る。

## 8.4 同表示を併合しない

0 と 1 はともに A だが、同じ節点へ潰さない。

潰すと次の advance が

$$
A\to A
$$

なのか

$$
A\to B
$$

なのか一意に定まらなくなる。

## 8.5 stay を reverse へ置換しない

Sol の第二操作は恒等操作。

$$
U_{stay}=id.
$$

往復運動ではない。

# 9. 逆コンパイル試験

この CMD 再記述から、元の第一稿の主要情報を復元できるかを確認する。

### 復元可能

- 状態数3。
- 読み取り $0,1\mapsto A$, $2\mapsto B$。
- stay / advance の二操作。
- advance の三状態巡回。
- A–Cの証人 $0|1$。
- stay の下での差の保持。
- Dの許容経路 α, β。
- Dの排除経路 γ。
- 終端拘束の始点・歩数・表示。
- 帰還後／同結果後の差が次の advance に効くこと。

### CMD図だけでは意図的に前面へ出さない

- $\mathbb Z_3$ の群としての一般式。
- 任意の操作列に対する閉形式
  $$
  U_w(z)=z+\sum a_k\pmod3.
  $$
- 状態数3の下界証明。

これらは「逆コンパイル用マニフェスト」および固定第一稿に残す。

従って CMD は数理原稿を削除する代替物ではなく、

> **同じ運動と差の追跡を前面に出す中間表現**

として扱う。

# 10. この再記述で新しく見えたこと

新しい定理を追加したわけではない。

ただし、元第一稿では別節にあった三つの主張が一本に見える。

```text
D[Z]  隠れている
  |
  | stay^n
  v
D[Z]  まだ隠れている
  |
  | advance
  v
D[O]  表示へ出る
  |
  | 同結果の別経路でも終端差として残り得る
  v
D[Z]  次の advance へ作用
```

この一本を、

- 保持側から見れば〈記憶候補〉
- 後続作用側から見れば〈原因候補〉
- 時間方向から見れば〈履歴候補〉

と注記できる。

語彙ごとに別の線を立てない。

# 12. Phase 2 への接続

CMD版 M0 から Phase 2 へ進む際の焦点は、

```text
D が残る
   ↓
D が参照 r を更新する
   ↓
更新された r が次の読み取り／選択を変える
   ↓
次の運動が変わる
   ↓
その運動が再び r を更新する
```

という閉ループ。

第一稿の $D$ をここで別の「記憶変数」へ置換しない。

差が状態側から参照側へ移るなら、

```text
D[Z] -> D[r]
```

と同じ追跡線の担持位置が変わったものとして記録する。

これが Sol 側 CMD 再記述から Phase 2 へ渡す最重要条件。
